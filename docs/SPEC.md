# AI 任务完成提醒工具 SPEC

- 版本：v1.0（2026-11-16，待用户批准）
- 规模判断：小工具。一个脚本、一个配置文件、安装与卸载各一个双击文件。

---

## 1. Problem Statement（问题陈述）

我在 Mac 上用 **Claude 桌面 App（Code 标签页）** 和 **Codex 桌面 App** 跑耗时较长的任务。AI 停下来之后，我常常不知道：

- **最难受的情况**：我彻底离开电脑（出门、通勤、睡觉），身边只有 iPhone。两个 App 自带的通知只在 Mac 上弹窗，手机收不到。
- 我离开座位但在附近，看不到屏幕。
- 我还在 Mac 前，但切到别的窗口干活，没注意到弹窗。

后果有两种：任务早就跑完了，我却晚了很久才回来看；更亏的是 AI 中途卡在"等我批准"上白白干等，而我以为它还在跑。

## 2. Proposed Solution（方案描述）

### 2.1 一句话

两个 AI 工具在"一轮跑完"或"要我批准"时，自动调用本机的一个小脚本；脚本判断值不值得打扰我，值得就通过**飞书群机器人**把消息推到我的 iPhone。

### 2.2 定位

- 只补"送到手机"这一块。Mac 上的弹窗继续由两个 App 自带的通知负责，本工具不重复做。
- 飞书消息在 Mac 版飞书上也会同步出现，顺带覆盖"在电脑前没注意弹窗"的情况。

### 2.3 触发时机

| 情况 | Claude Code | Codex |
|---|---|---|
| 一轮跑完，等我下一步指示 | 提醒 | 提醒 |
| 要我批准（执行命令、改文件等） | 提醒 | 提醒 |
| AI 向我提问 | 提醒 | 提问即一轮结束，按"跑完"提醒 |
| 出错中断（报错、额度用尽、断网） | 不做 | 不做 |

子任务（子 agent）结束不提醒，只在整轮结束时提醒。

### 2.4 打扰规则

满足以下**任一**条件才发飞书：

1. **任务跑得久**：从我发出指令到 AI 停下，超过 `任务时长门槛`（默认 120 秒）。
2. **我不在电脑前**：键盘鼠标已有 `离开门槛`（默认 180 秒）没动过。

"等我批准"多一步补查：批准请求出现时如果两个条件都不满足，脚本在 `离开门槛` 时间之后再看一次；若这段时间键盘鼠标始终没动过（说明我没回来批准），补发提醒。

"一轮跑完"不做补查。已知空档：任务很短，且我刚离开不到 3 分钟，这种情况不会提醒。这是为了不吵而接受的代价。

### 2.5 消息内容

包含：哪个工具、项目文件夹名、是"跑完"还是"等批准"、用时、内容摘要（AI 最后一段回复的前 100 字，或它想执行的命令，超过 100 字截断）。

```
✅ Claude Code 跑完了｜泡沫固井模拟｜用时 18 分钟
阶段 7-2 已合并进 main，两环境 3882 项测试通过。待你实测 Intel……
```

```
⏸ Codex 等你批准｜量化交易学习｜已运行 6 分钟
想执行：pip install pandas
```

多个任务同时跑时，每个任务各发各的，靠项目文件夹名区分。

### 2.6 发送失败时

1. 自动重试，共 3 次，每次间隔 5 秒。
2. 仍失败：在 Mac 上弹系统通知"飞书提醒发送失败：<具体原因>"，同时写入日志。
3. 不补发。过时的提醒没有意义，反而混淆。

### 2.7 安装与控制

- **安装**：双击 `安装.command`。它会让我粘贴飞书机器人地址，发一条测试消息确认能收到，然后往两个工具的钩子配置里各加几行（改之前先备份）。
- **Codex 额外一步**：安装后需在 Codex 桌面 App 的"设置 → Hooks"里手动点一次"信任"。安装脚本结束时用中文提示这一步。
- **卸载**：双击 `卸载.command`，只删除本工具加进去的那几行，不动其他配置。
- **调参数**：用文本编辑器改 `配置.ini`（带中文注释），可改两个门槛的秒数和摘要字数。
- **临时安静**：用飞书自带的群消息免打扰，本工具不做暂停开关。
- 没有界面，没有常驻后台程序。AI 不跑的时候，本工具不占任何资源。

### 2.8 考虑过的做法

| 做法 | 取舍 | 结论 |
|---|---|---|
| A. 两边都挂钩子，共用一个脚本 | 两家都提供官方钩子，"跑完"和"等批准"都有信号，还直接给出项目路径、最后回复、待执行命令。要改两处配置，Codex 要手动点一次信任 | **采用** |
| B. 常驻后台程序盯会话记录文件 | 不改配置，但记录格式官方明说不保证稳定，升级后可能悄悄失效；多一个常驻程序 | 否决 |
| C. Codex 接在 Computer Use 占用的 `notify` 接口前面转交 | 只有"跑完"信号，拿不到"等批准"；还要动已被占用的接口 | 否决 |

## 3. Technical Constraints（技术约束）

**运行环境**
- macOS；Python 用系统自带的 3.9.6，**只用标准库，不安装任何依赖**。
- 代码要我能读懂、能自己改：普通函数，不用类，不做抽象层。

**对接方式**
- Claude Code：钩子写在 `~/.claude/settings.json`。用到的事件：用户提交指令（记开始时间）、Stop（跑完）、以及权限请求 / 提问对应的事件。
- Codex：钩子写在单独的 `~/.codex/hooks.json`。用到的事件：UserPromptSubmit、Stop、PermissionRequest。
- **不修改 `~/.codex/config.toml`**，尤其不碰其中已被 Computer Use 占用的 `notify` 一行。
- 两个工具调用同一个脚本，通过参数说明自己是谁。
- 不读取会话记录文件，只用钩子直接交过来的字段。

**不拖慢 AI**
- 钩子脚本必须立刻返回。发飞书、重试、"等批准"的延时补查，都放到脱离钩子的后台子进程里做。
- 脚本不对钩子返回任何"允许 / 拒绝"的决定，批准仍由我自己点。

**判断依据**
- 任务时长：用户提交指令时按会话编号记下时间，停下时相减。
- 是否在电脑前：读取系统的键鼠空闲时间（`ioreg` 的 HIDIdleTime）。

**网络与隐私**
- 这台机器走代理，飞书在国内：发送请求必须**绕过代理直连**。
- 只向飞书机器人地址发请求，不连接其他任何外部服务。
- 机器人地址只存在本机配置文件里，文件权限设为仅本人可读；安装时校验地址必须是飞书机器人地址的格式，不是就报错并显示收到的值。
- 飞书机器人的安全设置用"自定义关键词"，关键词填 `Claude` 和 `Codex`。
- **已知并接受的外传内容**：项目文件夹名、AI 回复前 100 字、待执行的命令。如果命令里恰好带有密钥，也会被发出去。涉及不能外传内容的项目，应把配置里的摘要字数改为 0。

**出错处理**
- 不允许悄悄失败。配置缺失、钩子给的字段缺失、飞书返回错误，都要写日志并弹 Mac 通知，信息里带上导致出错的具体值。
- 日志是安装目录下的单个文本文件，超过 1 MB 时清空重写。

**位置**
- 安装目录：`~/开发/AI任务完成提醒/`。钩子里写的是这个目录的绝对路径，**挪动文件夹后需要重新双击安装**。

**开工第一步必须先实测（未证实项）**
- 官方文档确认两个工具都有上述钩子，但没有明说 Codex 桌面 App 里每个事件都生效，Claude 桌面 App 也需要在本机确认。
- 所以第一步是做一个只写日志的最小钩子，在两个桌面 App 里各触发"跑完"和"等批准"，确认 4 种信号都能收到、字段齐全。
- 如果有信号收不到：停下来如实告知，改 SPEC，不凑替代办法。

## 4. Non-goals（明确不做的事）

- 不做云端任务的提醒（网页版 Codex 云任务、Claude 云端会话不在本机运行，感知不到）。
- 不做 Mac 上的弹窗和声音（发送失败的告警除外）。
- 不做出错中断的提醒。
- 不做菜单栏图标、设置界面、暂停开关。
- 不做失败消息的补发，不做提醒历史记录。
- 不能在手机上回复 AI 或远程点"批准"，只是通知。
- 不支持飞书以外的通道（Bark、微信、钉钉、邮件）。
- 不支持其他 AI 工具，不支持终端命令行版和编辑器插件版的专门适配。
- 不支持 Windows，不考虑多人共用。
- Mac 休眠时任务本身会停，也就没有提醒，本工具不负责防休眠。

## 5. Success Criteria（成功标准）

全部可实测，逐条打勾才算做成：

1. **及时**：Mac 联网正常时，从 AI 停下到 iPhone 飞书响，不超过 10 秒。
2. **不漏**：Claude Code 和 Codex 各测"跑完""等批准"两种情况，共 4 种，全部收到。
3. **不吵**：我在电脑前连续快速对话 10 轮，手机一条都不响。
4. **等批准不白等**：我离开电脑不到 3 分钟时 AI 请求批准，在 `离开门槛` 时间后收到补发的提醒。
5. **看得懂**：只看手机上的消息，就能说出是哪个工具、哪个项目、是跑完还是等批准。
6. **不搞坏原有功能**：安装后 Codex 的 Computer Use 照常工作，`config.toml` 内容与安装前逐字相同；卸载后两个工具的钩子配置恢复到安装前的样子。
7. **失效可见**：断网测一次，Mac 上出现"发送失败"的弹窗，日志里有对应记录。
8. **不拖慢**：装上之后，AI 每一轮开始和结束没有可感知的卡顿。
9. **双击即用**：安装和卸载全程不需要我打开终端敲命令（Codex 里点一次"信任"除外）。
