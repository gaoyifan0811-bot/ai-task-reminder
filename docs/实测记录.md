# 实测记录

## 任务 0：钩子信号实测（2026-11-16）

环境：Claude 桌面 App（Code 标签页）、Codex 桌面 App（codex-cli 0.167.0）。
方法：两边挂一个只写日志的临时钩子，由用户在两个 App 里发指令触发。

### 钩子配置结构（两家相同）

```json
{"hooks": {"Stop": [{"hooks": [{"type": "command", "command": "..."}]}]}}
```

- Claude：写在 `~/.claude/settings.json` 的 `hooks` 键下，改完立即对所有会话生效，不用重启。
- Codex：写在 `~/.codex/hooks.json`；不需要功能开关。

### 结果

| 信号 | Claude 桌面 App | Codex 桌面 App |
|---|---|---|
| 开始 UserPromptSubmit | 收到。有 `session_id` `cwd` `prompt` | 收到。有 `session_id` `cwd` `prompt` `turn_id` |
| 跑完 Stop | 收到。有 `session_id` `cwd` `last_assistant_message` | 收到。字段同左 |
| 等批准 PermissionRequest | 收到（由提问工具触发）。有 `tool_name` `tool_input` | **待测**：`ls` 属于安全命令，没有触发批准 |
| 提问 | 走 PermissionRequest，`tool_name` 为 `AskUserQuestion`，问题在 `tool_input.questions[0].question` | 不适用 |

### 发现

1. Claude 提问时，PermissionRequest 之后约 6 秒还会再来一个 Notification（`notification_type` 为 `permission_prompt`，`message` 为英文套话）。两个都挂会重复提醒，所以**只用 PermissionRequest，不挂 Notification**。
2. 用户的 Claude 会话多为 `auto` 或 `bypassPermissions` 权限模式，平时很少弹批准；Claude 这边"等批准"主要就是"向你提问"。
3. 用户在 AI 运行中途追加消息时，会再来一次 UserPromptSubmit，开始时间被刷新。此时用户人在电脑前，按较短时长算是合理的，不处理。
4. Codex 新对话的 `cwd` 形如 `~/Documents/Codex/2026-11-16/new-chat`，文件夹名是 `new-chat`，辨识度低。属于 Codex 自身的命名，本工具照实显示。

## 任务 6：真机验收（2026-11-16 起）

安装方式：应用户要求由 Claude 操作桌面版飞书添加机器人，并用复制出的地址运行安装程序（未经双击，标准 9 待用户另行确认）。

| 标准 | 测法 | 结果 |
|---|---|---|
| Claude 提问提醒 | 本会话运行超过 2 分钟后调用提问工具 | **通过**：用户确认 iPhone 10 秒内收到「❓ Claude Code 在问你」 |
| Claude 跑完提醒（标准 1、2、5 的 Claude 部分） | 本会话一轮超过 2 分钟后结束 | **通过**：用户确认收到「✅ Claude Code 跑完了」 |
| 失效可见（标准 7）——本机模拟 | 把脚本副本的机器人地址指向本机一个没人监听的端口，直接运行发送 | 见下：重试 3 次后写日志并弹 Mac 通知。**不是真断网**，真断网一项待用户测 |
| Codex 跑完提醒（标准 1、2、5） | 用户在 Codex 桌面 App 发超过 2 分钟的任务 | **通过**（用户报告） |
| Codex 等批准提醒（标准 2、4） | 用户触发批准后离开键鼠 3 分钟以上 | **通过**（用户报告）。任务 0 遗留的"Codex 等批准信号待测"至此闭合 |
| 不吵（标准 3） | 用户连续快速对话 10 轮 | **通过**（用户报告手机未响） |
| 不搞坏原有功能（标准 6） | 卸载后比对 | **通过**：Claude 的 settings.json 与安装前备份内容相同；Codex 的 hooks.json 已删除；config.toml 的 notify 行未变。Computer Use 未实际试用 |
| 不拖慢（标准 8） | 计时 | 钩子单次 0.05–0.08 秒；验收期间用户未反映卡顿 |
| 全程无报错 | 查看日志 | 验收期间 日志.txt 为空 |

未做 / 未完全做到：

- **真断网（标准 7）**：只做了本机模拟，没有真的关 Wi-Fi 测。
- **双击安装（标准 9）**：安装是 Claude 代为运行的，「安装.command」「卸载.command」没有被真正双击过。
- **10 秒时限（标准 1）**：Claude 提问一项由用户确认在 10 秒内；其余几项用户只报告"通过"，没有秒表读数。
- **Computer Use**：只确认了它的配置行没变，没有实际用一次。
- 卸载测试后已重新安装；Codex 的信任记录仍在（4 条），重装后是否需要重新点信任未单独验证。
